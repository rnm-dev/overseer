# peon

> Автономный исполнитель задач разработки с интерактивной панелью наблюдения.

peon следит за Heroboard за задачами, назначенными бот-аккаунту, передаёт каждую задачу CLI coding-агента, проверяет результат, создаёт коммит и переводит задачу дальше по процессу. Локальная панель и API управления позволяют наблюдать за работой, не прерывая её.

![Маскот peon](assets/peon.png)

## Проект в двух словах

| Область | Возможности peon |
| --- | --- |
| Выполнение задач | Опрос очереди, подготовка промптов, запуск агентов, проверка, коммиты и продвижение задач |
| Агентские бэкенды | Claude Code по умолчанию; Codex доступен для явно выбранных сессий |
| Управление | Пауза и возобновление, статус, самообновление, отмена сессий и статистика использования |
| Наблюдение | Браузерная панель с живыми транскриптами, состоянием проектов, файлами и последними событиями |
| Интеграции | Heroboard и опциональный протокол Overseer для обнаружения узлов и передачи событий |
| Среда выполнения | Node.js 22+, TypeScript, Express и пользовательские сервисы systemd |

## Как задача проходит через peon

```text
Heroboard
    │  опрос назначенных задач
    ▼
Обработчик задач ──► промпт + контекст проекта
    │
    ▼
Coding-агент (Claude Code / Codex)
    │
    ├── события сессии ──► панель + API управления
    ├── изменения в рабочей директории
    ▼
Проверка ──► коммит ──► продвижение задачи
```

Сессии сохраняются на диск, поэтому демон может восстановить состояние после перезапуска. Панель использует те же хранилища и локальный API, что и CLI, благодаря чему состояние одинаково видно из обоих интерфейсов.

## Запуск peon

### Установка и старт

Требования: Linux с systemd, `git`, Node.js 22 или новее, `npm`, авторизованный CLI `claude` или `codex` в `PATH`, а также доступ к приватному репозиторию.

```sh
npm install -g git+ssh://git@github.com/rnm-dev/peon.git
peon start
```

Команда `peon start` устанавливает, включает и запускает два пользовательских сервиса:

- Интерфейс оператора: Overseer
- API управления: `http://127.0.0.1:4570`

Перед началом работы подключите интеграцию:

```sh
peon integration add <label> <apiUrl>
```

Полезные команды:

```sh
peon status                 # состояние, авторизация и доступность обновления
peon pause                  # остановить опрос, не останавливая сервисы
peon resume
peon update                 # обновить и перезапустить, если задача не выполняется
peon stop
```

## Для работы без постоянного надзора

Основные операционные ограничения и действия доступны непосредственно оператору:

- Для каждой задачи задаются максимум ходов агента, время выполнения и бюджет.
- Текущие сессии показывают транскрипты и могут быть отменены из панели или через API.
- Обновление не прерывает активную задачу без явного флага `--force`.
- Настройка и проверка проекта выполняются как отдельные типы сессий и видны в общей истории.
- Доступна статистика использования, стоимости, длительности и исходов сессий.

Настройки по умолчанию рассчитаны на осторожную автономную работу: опрос каждые 30 секунд, до 80 ходов агента, максимум 30 минут и бюджет $3 на задачу. Изменяйте их командами `peon settings` и `peon settings set <key> <value>`.

## Доступ и безопасность

По умолчанию оба сервиса привязаны к loopback. Доступ с другого компьютера организуйте одним из способов:

1. Пробросьте порты через доверенный SSH-туннель.
2. Включите прямой удалённый доступ командой `peon remote on <public-host-or-ip>`, создайте пользователей панели и используйте одноразовые ссылки авторизации.

```sh
peon user add alice
peon user auth-link alice
```

Открытые порты должны оставаться за доверенным межсетевым экраном или сетевой границей. Запрос через SSH-туннель выглядит для peon как локальный и поэтому проходит без входа в панель — сам туннель нужно защищать так же тщательно, как доступ к shell на хосте.

## Локальная разработка

```sh
npm ci
npm run dev
```

Команда запускает демон и панель с автоматической перезагрузкой на тех же портах, что используют установленные сервисы. Не запускайте её одновременно с systemd-сервисами.

Перед коммитом изменений в исходниках:

```sh
npm run typecheck
npm run compile
```

Команда `compile` собирает запускаемое приложение в `dist/` и копирует ресурсы панели. Скомпилированный код хранится в репозитории, потому что CLI устанавливается и запускается из этой сборки.

## Основные настройки

```sh
peon settings
peon settings set maxTurns 80
peon settings set taskTimeoutMs 1800000
peon settings set maxBudgetUsd 3
peon settings set agentCommand claude
peon settings set codexCommand codex
```

Полный список настроек и детали развёртывания смотрите в [`README.md`](README.md). Описание API для взаимодействия между машинами — в [`PROTOCOL.md`](PROTOCOL.md).
